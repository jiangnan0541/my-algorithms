# 排序算法基准实测

> 脚本：`benchmarks/benchmark_sorting.py`
> 复现：`python benchmarks/benchmark_sorting.py --sizes 200,1000,2000`
> 方法：`timeit` 每项测 3 次取**最小值**（最小值比均值更能排除系统调度噪声）
> 环境：Windows 11 / Python 3.11.16 (Anaconda) / Intel Core Ultra 5 125H
> 值域：`random.randrange(1, 100_000)` —— 收窄值域是因为计数/基数排序直接按值大小开数组

绝对值随机器波动，**只看相对关系**。

## 读这张表能得出什么

**1. 选择排序的耗时和输入完全无关。** 五种分布全是 91–104 ms。
因为它的比较次数恒为 n(n-1)/2，不因输入而变。这是教科书里
"选择排序无最好/最坏之分"最直观的实测印证。

**2. 冒泡的 early-exit 真的省了两个数量级。** random 204 ms → sorted 0.11 ms，
约 **1800 倍**。没有提前退出的教科书版本在 sorted 上一样要跑满 n² 次比较。
代价是判断多一行 `if not swapped: break`。

**3. 插入排序在"近似有序"上的优势巨大。** 2% 元素位置错乱时只要 2.63 ms，
比完全随机的 86.5 ms 快 **33 倍**。这正是很多标准库
（CPython 的 Timsort、Java 的 DualPivotQuicksort）对小数组或近似有序段
切换成插入排序的原因。

**4. 计数排序被值域吃掉了。** 值域 10 万、n 只有 2000 时，它要 4.44 ms ——
比 O(n log n) 的归并还慢。因为 O(n + k) 里的 k = 100000 完全主导。
同一份代码在 all-equal 上只要 0.15 ms（此时 k 退化成 1）。
**结论：非比较排序的常数项是值域宽度，不是元素个数。**

**5. 基数/桶排序在这组数据里最快（0.7–0.9 ms），但这个结论有前提。**
它们是按"数值区间切分"工作的，前提是值域窄、分布均匀。
换成字符串、或者值域跨度 10^9，桶会退化成单桶 + 插入排序，直接掉到 O(n²)。

**6. 同为 O(n log n)，常数差异值得注意。**
quick 2.79 ms < heap 3.23 ms < shell 2.83 ms < merge 4.28 ms。
归并慢是因为每层合并都要 new 一个列表（O(n) 额外分配）；
堆排慢是因为 sift-down 的缓存局部性差。
另外 shell 在 sorted 上（1.43 ms）比快排（1.92 ms）还快 —— 折半增量
在近似有序输入上收敛极快。

**7. 快排在三等值输入上只要 0.18 ms。** 因为本实现是三路切分
（`< pivot` / `== pivot` / `> pivot`），全等值一次就分完，直接退化到 O(n)。
两路切分的实现在这个分布上会退化成 O(n²) —— 这也是 n=2000 时
heap（0.57 ms）能反超 quick 的原因之一（堆排在三等值下也受益于堆性质）。
